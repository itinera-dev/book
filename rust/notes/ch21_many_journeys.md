In Rust, `Orders::builder()` starts a new instance, `initial_data` gives it the order, and `create` makes it. `create` can fail before any journey, with an `InstanceError`, when the workflow's ID generator or a reporter fails while the instance is made; that is not a refusal, since the executor is not involved yet. `run` takes the instance by value, so an instance cannot run twice, and it borrows the executor mutably, so one executor cannot run two journeys at once: both mistakes are compile errors rather than refusals. To run journeys in parallel, give each thread its own `LocalExecutor`. On the asynchronous executor, `AsyncLocalExecutor`, the loop is the same, with the call to `run` awaited.
