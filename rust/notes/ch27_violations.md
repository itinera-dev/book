In Rust, `#[workflow(...)]` checks the declaration while the program compiles, so a workflow declared with it and holding these mistakes does not compile at all. This example declares the shop with `WorkflowDescriptor::builder` instead, as chapter 28 shows, so that the program compiles and the violations appear when it runs. `build()` returns `Result<WorkflowDescriptor<W>, Violations>`. `Violations` holds every violation found, in a fixed order, and each `Violation` displays as the specification names it, followed by what it concerns; `kind()` gives its `ViolationKind` for code that needs to tell them apart. One mistake the builder cannot return as a violation panics while the workflow is declared, with a message saying what was wrong: two input adapters of one name. An empty step name does not compile, since `step_name!` checks it.
