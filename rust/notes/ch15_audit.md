In Rust, each hook is a method of the policy's `impl` block, marked with the hook it is: `#[on_step_success]` returns `Result<Option<OnSuccess>, Error>`, and `#[on_step_failure]`, `#[on_step_retry]` and `#[on_step_abnormal_termination]` return `Result<Option<FailWorkflow>, Error>`. Each parameter after `&self` says what it asks for: `#[step_name]`, `#[from_step]` for a contribution of the step, keyed by the parameter's name, `#[reason]` for the failure's reason, `#[contributor]`, and the others listed in the API reference of `step_policy`. A request that a hook cannot make, such as the reason on success, does not compile. A parameter of type `Option<T>` is an optional request; any other type is required, and a required request with no value aborts the journey.

A hook that returns `Err` aborts the journey with `hook failed`: a hook cannot fail and carry on. In the asynchronous form, the hooks are `async fn`, which makes the whole policy asynchronous, and it can then be attached only to the steps of a workflow declared `asynchronous`.
