A step's contributor and step reporter are made only by the executor, for one attempt, so a step cannot be called on its own: a test runs it in a small workflow of its own, as `ChargeAlone` does, and the same goes for a policy whose hooks take a contributor. The workflow's own state, here the `outbox` field, is given to each instance on its builder, which is how a test creates an instance with a fake. The instance and its reporters move into `run`, so the fakes keep what they receive by sending it down a `std::sync::mpsc` channel, whose receiving end the test keeps. The `Messages` role's `tell` returns nothing, so the fake outbox cannot hand a failure back through it: if the test has stopped reading, the fake panics, and itinera never catches a panic, so the test fails as a failed assertion would. In a crate, the same checks sit in a test module, `#[cfg(test)] mod tests`, one `#[test]` function per check, named after the rule it checks, such as `a_free_order_is_never_shipped`, with `assert_eq!` in place of the `check` helper; `cargo test` then runs them all and reports each one.
