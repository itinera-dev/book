The Rust edition follows the crate `itinera` at the commit this book's `Cargo.toml` pins, on its way to the release `0.1.0-rc.1`. Services and rescue steps arrive before `0.1.0-rc.1`: the crate cannot be released until every tier 1 proposal is in its report, those two included.

Its report is [`conformance.json`](https://github.com/itinera-dev/itinera-rs/blob/main/conformance.json), in the crate's repository. At this commit it runs the conformance cases `v0.1.0-rc.8`, lists every proposal of specification 0.1 as passing, and claims both capabilities: `LocalExecutor` runs synchronous workflows and, with the `async` feature, `AsyncLocalExecutor` runs asynchronous ones. Neither runs a workflow of the other mode: that is a compile error, not a refusal.

It lists these rules as impossible to write in Rust, each with the test that proves it: a lifecycle a hook may not return (`invalid-lifecycle`), a policy needing a role the workflow does not provide (`role-not-provided`), something that is not a value in the data bag, initial data, an input adapter's answer, a reason's details or an event (`non-value`), an asynchronous step on the synchronous executor (`mode-not-accepted`), a handle used after its attempt or call (`late-handle`), and a write through an input adapter's access to the data bag (`bag-write`).
