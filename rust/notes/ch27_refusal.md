In Rust, `run` returns `Result<JourneyResult, Refusal>`. `Refusal` says what refused the journey and carries its error: `WorkflowPolicy` when a workflow policy failed while it was built, with the policy's name, and `DispatcherFactory` or `Dispatcher` when the dispatcher failed. A policy declared with `#[workflow_policy]` is built with `Default` unless one function of its block, marked `#[factory]`, builds it; a factory that returns a `Result` may fail, as here. Creating the instance may fail before that, with an `InstanceError`, when the ID generator or a reporter fails; no executor is involved yet. Running an asynchronous workflow on `LocalExecutor`, initial data that is not a value, and running one instance twice do not compile, so `run` never refuses for them.
