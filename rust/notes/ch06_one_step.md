In Rust, a step is a struct and an `impl` block. Deriving `Step` makes each field marked `#[input]` an input, named after the field. The `#[step]` attribute on the block declares `run`, which takes the step by value and returns `Result<Outcome, Error>`; `Self::succeed()` and `Self::fail(...)` build the outcome.

The journey's data are plain structs too. Deriving `InitialData` on `NewOrder` makes each of its fields a key of the initial data, and `Orders::builder().initial_data(...).create()?` creates the workflow instance with them. `run` returns `Result<JourneyResult, Refusal>`: the `Err` side is only for a journey that could not start, so a journey that failed is still `Ok`, and `result.status` says how it ended. Deriving `Output` on `Charged` lets `result.output()` read the data bag into that struct, one field per key; it returns an error when a key the struct needs is missing, which is why the program stops with an error when the price is 0.

A step whose `run` is an `async fn` is asynchronous, and runs only in a workflow declared `asynchronous`, on the asynchronous executor. A synchronous step in an asynchronous workflow, or the reverse, does not compile.
