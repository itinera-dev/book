A reporter implements the `Reporter` trait, whose `report` receives each `&Event` and returns `Result<(), Error>`: an `Err` is a reporter that fails. What an event says is in `event.body`, an `EventBody` with one variant per kind, which `event.kind()` names in snake_case. The reporters listed in `#[workflow(reporters = [Log])]` are made with `Default` for every journey; `.reporter(...)` on the instance's builder adds one for that journey alone. The default dispatcher calls the reporters in the order they were added: first those the workflow lists, in their order, then those the instance adds, which is why the log receives each event before the archive. A step requests its step reporter with a `#[reporter]` parameter of type `StepReporter<'_>`, and propagates what `info` returns with `?`: if a reporter fails on that event, the step ends there, and the journey is aborted whatever the step does next. In the asynchronous form, reporters implement `AsyncReporter`, with an `async fn report`, the workflow lists them under `async_reporters`, the instance adds one with `.async_reporter(...)`, and the step's `AsyncStepReporter` is awaited.
